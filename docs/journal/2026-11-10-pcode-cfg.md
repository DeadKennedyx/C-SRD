# Bounded P-code control-flow reconstruction

## Observation and question (before implementation)

The saved-answer replay resolved all ten previously inconclusive Jenkins limb
grades. Five measured GCC-original attempts still have no answer because the
adapter rejects its four-iteration loop and merge nodes. This is an observer
coverage gap, not evidence that the original program is protected. The old
export's address-ordered operation list even places some uses before definitions;
it cannot serve as execution order.

Can an explicit, conservatively validated control-flow export reconstruct this
fixed loop and independent bounded branch/merge examples without accepting a
partial expansion as a complete function?

## Design and predeclared protocol

Add schema 2 with basic-block operation order, entry block, and both directions
of every edge, including reverse edge indexes. Keep schema-1 expression DAG
replay. Reject missing, inconsistent or ambiguous control-flow information.
Check operation types, SSA definitions, dominance and phi-edge associations.
Evaluate all phi inputs simultaneously at entry. Explore both successors of an
unknown condition; only exact constant evaluation may remove a successor.
Every explored path must return within the bounds. Otherwise reject the entire
answer. Emit pure unsigned expressions/selects, with no memory effects.

Initial fixed limits: 4,096 nodes, 2,048 operations, 256 blocks, 64 block entries
per path, 1,024 total block expansions, 64 terminal paths, 65,536 evaluated
operations, 16,384 emitted C statements and 1 MiB generated C. These constrain
this observer, not candidate runtime/size selection. Full-domain source-model
grading remains separate from lifting and reconstruction.

Development controls: diamond branches, parallel edges, nested branches,
constant-count loops, simultaneous phi swaps, invalid SSA/edges/widths, effects
outside the return slice and nontermination/budget exhaustion. Use a separate
concrete graph interpreter and independently written C functions; mutate an
edge/value to require a counterexample. Run real Ghidra on the frozen GCC Jenkins
original and retain historical exports/statuses unchanged.

Reserve before implementation two observer validation shapes: unsigned absolute
difference selected by comparison, and a five-step unsigned affine recurrence
with a conditional increment. Compile them with GCC and Clang at O1/O2 after
development controls pass; do not tune the adapter on their results. These are
small observer validation examples, not a representative protection corpus. The
existing reserved reconstruction algorithm families stay closed.

Measure any final observer resource run serially after tests/builds. Preserve
raw commands, tool/source/binary hashes, failure logs and unchanged old evidence.
Acceptance requires correct real reconstruction under the source model and
passing negative controls. Unsupported validation cases stay explicit.

## Scope decision

The inspected wide-data failures also contain vector `CALLOTHER` intrinsics and
unusual byte widths. Scalar 64-bit support alone would not resolve them. Defer
wide/vector semantics to a separate bounded specification rather than adding
untested arithmetic to this control-flow change. No new protection candidate or
C language support is implied by observer coverage.

## Prototype and development controls

Implemented shared scalar value rules, checked CFG/SSA metadata, and complete
bounded expansion. The first real prototype recovered the unchanged GCC O2
Jenkins original: three blocks, four constant-controlled iterations, six block
entries and one terminal path. Its 1,098-byte C answer passed the full-domain
source-model comparison; the result-plus-one control produced a counterexample.
No change to the original binary, transformer or language subset was needed.

Six new test methods cover seven valid graphs, seven wrong-output proofs, an
incorrect parallel-edge merge, 21 metadata/type/SSA mutations plus an off-slice
effect, three expansion failures and simultaneous merge/metric checks. Seven
graphs on 209 vectors each matched an independent concrete interpreter under
GCC/Clang O0/O2 and Clang ASan/UBSan (7,315 compiled comparisons per platform).
All 19 CTest groups passed on macOS (79.40 s) and Linux ARM64 (58.08 s); Linux
also enabled the real Ghidra integration. Those durations are test-suite wall
times during overlapping native/container testing, not benchmark timings.

Freeze the adapter after these development checks. Next run the two prespecified
validation shapes without tuning on their outcomes, then a serial repeated
GCC-original recovery check. Retain the first pilot separately from final trials.

The validation-matrix pilot stopped before compiling/decompiling the recurrence:
the existing frontend requires canonical `++i`, while its fixture used
`i = i + 1u`. The eight distance build cells had completed. Preserve that failed
run and the rejected source, then correct only the recurrence counter syntax and
rerun in a new directory. Its five-step behavior and all adapter rules remain
unchanged. This is a fixture-admission correction before observer results, not
adapter tuning on validation outcomes.

## Reserved validation and supplemental checks

The corrected matrix completed all 16 original/identity build cells for the two
validation shapes at GCC/Clang O1/O2. The frozen adapter emitted answers for all
16; twelve passed the source-model proof. GCC's recurrence expanded 32 terminal
paths (157 block entries for the original, 94 for identity). Its answers proved.
The four Clang recurrence answers use compact mask arithmetic but their grader
timed out. All 16 wrong-output proof controls were rejected.

After observing those gaps, replayed the four frozen mismatch queries using the
already validated circuit backend, without changing answers or observer rules.
They represent two distinct queries. All four remained inconclusive at the
existing five-second ABC budget; all seven replay controls passed. Retain both
sets of grades. This does not support any reconstruction-resistance conclusion.

Added a separate finite checker after these proof failures. It compares each
saved answer with the frozen original executable and an independently written
integer oracle, using 64 boundary pairs plus 2,048 deterministic random pairs.
GCC/Clang O0/O2 and Clang ASan/UBSan produced 80 successful answer builds and
168,960 matching comparisons. All 80 wrong-output builds disagreed on every
input (another 168,960 comparisons). The four proofs remain unresolved; tests
are supplemental evidence, and the correlated controls are not a population
false-positive estimate. No original observation was modified.

## Repeated recovery and decision

The final serial Jenkins run excluded one warmup and measured five repetitions
of the same frozen GCC O2 binary. All five recovered answers proved under the
source model and all five controls produced counterexamples; the warmup passed
too. Median whole-observer wall/CPU were 5.090/5.979 seconds, peak process RSS
420.5 MiB and sampled aggregate RSS 452.7 MiB. The JSON/reconstruction/write stage was median
0.844 ms; separate grading was 21.40 ms. These describe this observer and host,
not a speedup versus its earlier incomplete attempts or human analysis effort.

The [report and evidence](../../reports/pcode-control-flow.md) retain the pilot,
fixture-admission failure, successful matrices, all proof/test outcomes and raw
measurements. Publish CFG coverage while explicitly retaining wide/vector and
grading limitations. Resume candidate comparisons using additional positional
widths and algorithm choices, with reconstruction resources, runtime and size
reported before imposing any cost ceiling. No protection winner is established.
